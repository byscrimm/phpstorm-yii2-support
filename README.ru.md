# PhpStorm Yii2 Support

[English](README.md) | Русский

Поддержка Yii2 для PhpStorm / IntelliJ IDEA: автодополнение, навигация, связи ActiveRecord, представления, конфигурация, маршруты, переводы и миграции.

[phpstorm-yii2-support](https://github.com/byscrimm/phpstorm-yii2-support) — форк [vxdy/Yii2-Support-Extended](https://github.com/vxdy/Yii2-Support-Extended), основанного на [nvlad/yii2support](https://github.com/nvlad/yii2support). **Все обновления, исправления, доработки и изменения документации в этом форке выполняются с помощью AI под руководством владельца репозитория.** Это относится к развитию форка; авторство исходного кода сохранено. Подробнее: [AI_DEVELOPMENT.md](AI_DEVELOPMENT.md).

AI используется в процессе разработки. Для анализа Yii2-кода плагину не нужен AI-сервис или API-ключ. Сохранены лицензия и ID `com.yii2supportExtended`.

Основная целевая IDE — PhpStorm 2026.2. Поддержка IntelliJ IDEA требует совместимых PHP и Database Tools; отдельно эта конфигурация не проверена.

Целевая ветка IDE: **262.***, Java 25. Текущая версия: **1.1.0-rc.1**. Полный план развития и его статус: [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md).

## Что добавлено в 1.1

- Дополнение связей в `with`, `joinWith`, `innerJoinWith`, `getRelation` и `via`.
- Вложенные пути: `orders.items.product`; массивы с callback и JOIN-алиасы (`orders AS o`).
- Переход к getter каждого сегмента пути; переименование сегмента сохраняет остальные части строки и алиас. Добавлен поиск строковых использований по имени связи.
- Модель определяется по `Model::find()`, поддержанным цепочкам Query, локальным переменным, `new ActiveQuery(Model::class)` и вызовам relation-getter.
- В подсказках остаются публичные relation-getter с `hasOne`/`hasMany`. Обычные getter, SQL-строки и аргумент типа JOIN исключены.
- Общий обработчик именованных аргументов и исправления определения ключей массивов для ссылок на конфигурацию и параметров URL.
- Последний `asArray(false)` корректно отменяет предыдущее `asArray()` при выборе режима type provider.
- Автоматические тесты на настоящем PHP PSI из SDK PhpStorm; отдельная проверка JVM-ссылок; ZIP создаётся после успешных запрошенных проверок.

Примеры:

```php
User::find()->with(['orders.items.product']);
User::find()->joinWith(['orders AS o' => function ($query) {
    $query->andWhere(['o.status' => 1]);
}]);

$query = User::find()->where(['active' => 1]);
$query->with('orders');
$user->getRelation('orders');
```

## Остальные возможности

| Область | Возможности |
| --- | --- |
| ActiveRecord / ActiveQuery | Подсказки связей, вложенные пути, переход к relation-getter, определение типов `one()` / `all()` в поддержанных сценариях |
| Представления | Подсказки имён и параметров view, переход к файлам, проверки отсутствующих view и параметров |
| Конфигурация | Подсказки свойств в массивах, `Yii::createObject()`, компоненты `Yii::$app`, настройки виджетов |
| Формы и модели | Атрибуты в ActiveForm/HTML-хелперах, `rules()`, `attributeLabels()` |
| База данных | Подсказки таблиц и столбцов, проверки ActiveRecord, SQL-параметры и исправления с сохранением существующих значений |
| URL | Подсказки маршрутов и параметров action, переход к контроллерам в поддержанных сценариях |
| i18n | Подсказки категорий и сообщений из PHP-каталогов переводов |
| Миграции | История, применение/откат/повтор через UI, вывод команд и синхронизация выбранного источника данных |

Часть возможностей унаследована и пока не прошла полный набор проверок в интерфейсе IDE. Динамические конструкции могут не распознаваться; завершённые и запланированные этапы разделены в плане.

Для подсказок столбцов требуется настроенный источник данных в IDE. Корень Yii, представления, источник данных и миграции настраиваются в **Settings → PHP → Yii2 Support**.

## Установка

1. Соберите плагин одним из способов ниже; ZIP появится в `build/distributions`. Если опубликован подходящий релиз форка, можно использовать его ZIP. Исходный архив GitHub **Code → Download ZIP** не является установщиком плагина.
2. **Settings → Plugins → ⚙ → Install Plugin from Disk…**.
3. Выберите ZIP и перезапустите PhpStorm. Распаковывать ZIP не нужно.

## Сборка через Docker

Нужен Docker с BuildKit и доступ к репозиториям зависимостей при первой сборке:

```sh
make docker
```

Команда запускает тесты и экспортирует ZIP в `build/distributions`. Образ собирается на Java 25; временный именованный контейнер не создаётся. Docker-сценарий подготовлен, но в текущей локальной среде не запускался.

## Сборка без загрузок через установленный PhpStorm

Нужны Python 3 и установленный PhpStorm 2026.2 с JDK 25:

```sh
python3 tools/build-offline.py --test --psi-test
python3 tools/verify-offline.py
```

На другой системе укажите SDK:

```sh
python3 tools/build-offline.py --ide /path/to/PhpStorm --test --psi-test
python3 tools/verify-offline.py --ide /path/to/PhpStorm
```

Можно использовать `PHPSTORM_HOME`; если встроенный runtime не содержит `javac`, укажите `--java-home /path/to/jdk-25` для сборки. PSI-тестам также нужен JDK 25: `JAVA_HOME` либо встроенный JDK. Инструменты проверок используют тестовые каталоги внутри `build`, не меняя рабочие настройки IDE.

Вместе с ZIP создаются SHA-256 и `build-info-<version>.json`, где указаны SDK и выполненные проверки. Архив не содержит исходников тестового приложения или библиотек IDE.

## Gradle и CI

JDK 25 и Gradle Wrapper 9.1.0:

```sh
./gradlew check buildPlugin
./gradlew verifyPlugin
```

При наличии установленного SDK:

```sh
./gradlew -PlocalIdePath=/path/to/PhpStorm check buildPlugin
```

Gradle-плагин, тестовый framework и Plugin Verifier могут потребовать скачивания даже при локальном SDK. Workflow GitHub Actions подготовлен для тестов, Plugin Verifier и сохранения артефактов.

## Границы проверки и текущие ограничения

- Локальные Core-тесты используют настоящий PHP-парсер/PSI и проверяют разрешение связей и обработчик переименования. Таблица классов в них задаётся тестом; полный индекс PhpStorm и интерфейс автодополнения эти тесты не запускают.
- `verify-offline.py` проверяет JVM-классы/методы/поля и дескриптор относительно установленного SDK. Он не заменяет JetBrains Plugin Verifier и тесты поведения IDE.
- Полный тестовый профиль IDE требует действующей активации. Для отдельного запуска предусмотрен `tools/smoke-ide.py`. История проверок сохранена в [отчёте](docs/verification/1.1.0-rc.1.md).
- Полный Plugin Verifier и Gradle/Docker-сборка пока не подтверждены выполнением. Статус меняется только после фактического запуска и обновления отчёта.
- Неоднозначные присваивания, динамические фабрики и произвольные пользовательские Query-методы могут оставаться без подсказок. Плагин не исполняет PHP-код проекта для анализа.
- Вывод модели из GridView `dataProvider`, расширение поддержки views, полноценное слияние конфигов/DI и настройка источников i18n — следующие этапы плана, а не возможности завершённого этапа 1.1.
